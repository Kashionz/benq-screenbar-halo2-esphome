# HaloDesk 外部控制規劃

狀態：規劃中，尚未實作。本文件只描述預定行為；實機結果待實作後記錄於 [開發驗收紀錄](DEVELOPMENT_ACCEPTANCE.md)。

## 目標

讓 Stream Deck 這類外部裝置與工具不必打開控制面板，只要 HaloDesk 開著，按一下就能切換情境或開關燈。以通用性為主：不綁定特定廠牌、不需要安裝 App 專用插件，任何能「執行程式」「開啟網址」或「送出按鍵」的工具都能使用。

不列入本規劃：本機 HTTP／WebSocket API、Stream Deck 官方插件與按鍵狀態回顯、以網址或命令列調整亮度與色溫、App 未開啟時執行情境與開關燈以外的動作。

## 觸發方式

三種觸發方式共用同一套動作字串（見下節），全部轉成同一種意圖交給主視窗。亮度與色溫調整只能用全域快捷鍵觸發，網址與命令列不接受。

| 方式 | 寫法 | 適用 |
| --- | --- | --- |
| 命令列參數 | `halodesk.exe --action preset/1` | 能執行程式的工具：Stream Deck「系統 → 開啟」、Loupedeck、Touch Portal、AutoHotkey、批次檔、工作排程器 |
| 自訂網址 | `halodesk://preset/1` | 能開網址的工具：Stream Deck、Raycast／Alfred、macOS 與 iOS 捷徑、NFC 標籤 |
| 全域快捷鍵（選用） | 使用者自訂組合鍵 | 只能送出按鍵的裝置：巨集鍵盤、滑鼠側鍵、鍵盤巨集鍵 |

- 命令列：App 已開著時，第二次啟動由 `tauri-plugin-single-instance` 把參數轉給既有實例後立即結束，不開第二個視窗。這也一併處理目前重複啟動會出現第二個實例的情況。
- 網址：由 `tauri-plugin-deep-link` 接收；Windows 上網址同樣以參數形式送到 single-instance。
- 快捷鍵：由 `tauri-plugin-global-shortcut` 註冊，預設全部未設定；組合鍵已被其他程式佔用時，設定頁顯示註冊失敗，不改用其他組合。

## 動作

只接受下列字串（不分大小寫、長度上限 128、僅 ASCII），其他一律丟棄，不嘗試猜測或修正。

### 網址、命令列與快捷鍵皆可使用

| 動作 | 行為 |
| --- | --- |
| `power/on`、`power/off` | 送出明確的開燈／關燈；目標已是該狀態時不送命令，與系統匣選單停用對應項目一致 |
| `power/toggle` | 依最新讀取的目標電源，送出明確的開燈或關燈；不送切換指令 |
| `preset/1` … `preset/4` | 依情境列表位置套用 |
| `preset/<uuid>` | 依情境 id 套用；改名、刪除其他情境或重排都不影響 |
| `preset/next` | 套用目前相符情境的下一個（循環）；沒有相符情境時套用第一個 |

### 只限全域快捷鍵

亮度與色溫調整不開放網址與命令列格式；`halodesk://brightness/up` 或 `--action brightness/up` 視為未知動作丟棄。以下名稱僅是快捷鍵設定與內部事件使用的識別：

| 動作 | 行為 |
| --- | --- |
| `brightness/up`、`brightness/down` | 目前模式點亮的每一路亮度 ±10，限制在 1–100 |
| `temperature/warmer`、`temperature/cooler` | 色溫 −250／+250 K，限制在 2700–6500 K |

- 「相符情境」：目前目標的模式、點亮那幾路的亮度與色溫都與情境相同。
- 加減步進以主視窗目前顯示的值（目標 ⊕ 已送出 ⊕ 未送出）為基準，已在上下限時不送命令。
- 情境套用與現有情境點選相同：只送與目前目標不同的欄位，電源維持原設定。
- 位置版連結在刪除或重排情境後會指到另一個情境；需要固定對應時使用 id 版。

## 執行規則

外部觸發與系統匣選單相同，不直接連線橋接器，只把意圖送給主視窗；主視窗仍是唯一的命令協調者，沿用既有命令流程。

1. Rust 端解析動作後，以 `halo-external-action` 事件送到 `main`，每次觸發一筆，Rust 端不重試、不暫存（冷啟動的一筆暫存見「App 未開啟時」）。網址與命令列使用的解析函式不接受只限快捷鍵的動作。現有 `halo-flyout-intent` 格式不變；`power/toggle`、`preset/next` 與加減步進需要讀取狀態才能換算，因此由主視窗解析成 `power()` 或 `adjust()`。
2. 主視窗視窗隱藏時會停止 2 秒輪詢，快照可能過時。外部動作在視窗隱藏或上次讀取已超過 2 秒時，先讀一次狀態（GET）再換算；快速連按時不重複讀取。
3. 換算後使用與主畫面相同的 `power()`／`adjust()`。連續的燈光調整由現有 live 傳送合併：間隔至少 500 ms，中間值丟棄，不排隊。
4. 下列情況直接丟棄，不排隊、不稍後補送：未連線、離線、無線模組未就緒、上一筆結果不明、明確命令處理中、情境不存在。
5. App 未開啟時，命令列或網址會啟動 App；後續處理見下節「App 未開啟時」。
6. 每次實際送出都是一筆 RF 命令，照常寫入診斷紀錄。
7. 被拒絕時發一則系統通知（`tauri-plugin-notification`），說明原因；成功不通知。「處理中」不通知，避免連按時大量跳出；同一原因 5 秒內不重複。通知預設開啟，可在設定關閉。

## App 未開啟時

情境動作（`preset/1` … `preset/4`、`preset/<uuid>`、`preset/next`）與 `power/on`、`power/off` 會打開 App 並執行；其他動作只打開 App，動作丟棄。

1. App 正常開啟主視窗。啟動時帶入的動作由 Rust 端暫存一筆，主視窗載入後以一次性 command 取走（取走即清除），避免事件在前端監聽建立前送達而遺失。macOS 冷啟動時網址由事件送達，同樣存入這一筆。
2. 有已保存的連線時，自動以「使用已保存帳密連線」相同流程連線一次：讀取系統憑證、核對裝置識別。裝置識別不符時拒絕，與手動連線相同。
3. 連線成功後以連線時讀到的狀態執行，流程與開著時相同：情境只送不同欄位、電源維持原設定，`preset/next` 以這次讀到的狀態判斷相符情境；開燈／關燈依這次讀到的目標判斷，已是該狀態時不送命令。
4. 只嘗試一次，不重試。下列情況丟棄動作、停在連線頁並發通知說明原因：沒有已保存的連線、憑證讀取失敗、連線失敗或逾時、裝置識別不符、連線後處於鎖定（無線模組未就緒、結果不明等）、情境不存在。
5. 暫存的動作只用於這次啟動的第一次連線；使用者在連線完成前手動操作連線頁（輸入帳密、搜尋或按連線）時丟棄，不在之後的連線補套用。
6. 只有外部動作觸發的啟動會自動連線；一般開啟 App 的行為不變，仍不自動連線、不自動套用。
7. App 已開著但未連線（例如使用者手動中斷）時不自動連線，依「執行規則」第 4 點丟棄。

## 設定頁「外部控制」

「設定」新增「外部控制」分頁，與「裝置與連線」「外觀」「診斷紀錄」並列：

- 動作對照表：電源與情境動作同時列出網址與命令列寫法，可一鍵複製；4 個情境各列位置版與 id 版，並說明兩者差別。命令列寫法使用目前執行檔的實際路徑。亮度與色溫不列入對照表。
- 快捷鍵：每個動作（含亮度與色溫調整）可指定或清除一組全域快捷鍵（情境以位置指定），註冊失敗時顯示原因。
- 通知開關：被拒絕時是否顯示系統通知。

情境編輯模式不增加任何按鈕。設定保存在 App 資料目錄（例如 `external.json`，原子寫入），不含帳密、IP 或裝置識別。

## 平臺

| 平臺 | 網址 | 命令列 | 快捷鍵 |
| --- | --- | --- | --- |
| Windows | NSIS 安裝時登記 `halodesk://`；開發版在執行時登記目前使用者 | `halodesk.exe --action …` | 支援 |
| macOS | Info.plist 宣告 URL scheme，僅打包後的 App 有效 | 以 `open "halodesk://…"` 代替 | 支援，需實測輔助使用權限需求 |
| iOS | Info.plist 宣告 URL scheme；觸發會把 App 帶到前景 | 無 | 無 |

## 安全

- 只接受固定動作字串，不代理任意網址、檔案路徑或 shell 命令，也不新增這類 Tauri commands。
- 動作字串與網址不帶帳密、配對位址、IP 或裝置識別，也不會回傳任何資料。
- 任何本機程式或網頁都能開啟 `halodesk://`（瀏覽器會先詢問使用者）；影響範圍與手動按下 App 上的按鈕相同，且受同一套鎖定與不重送規則限制。
- 新插件的權限只授予主視窗；系統匣面板的 capability 不變。

## 實作順序

1. **Rust 動作解析**：`src-tauri/src/external.rs` 的解析函式與單元測試（合法字串、大小寫、未知動作、超長、非 ASCII、位置超出 1–4、不合法 UUID，以及網址與命令列拒絕亮度、色溫動作）。
2. **觸發接入**：加入 single-instance 與 deep-link 插件，命令列與網址都送 `halo-external-action`；冷啟動帶入的動作暫存一筆，提供一次性取走的 command。
3. **主視窗處理**：解析 `halo-external-action`，實作讀取新鮮狀態、`power/toggle`、`preset/next`、加減步進與拒絕原因；前端測試涵蓋過時快照、上下限、鎖定時丟棄、處理中不通知。
4. **冷啟動執行**：主視窗載入時取走暫存動作，情境與開燈／關燈動作以已保存連線自動連線一次後執行；測試涵蓋無保存連線、連線失敗、裝置識別不符、連線後鎖定、目標已是該電源狀態、使用者先手動操作、其他動作丟棄、一般啟動不自動連線。
5. **通知與設定頁**：拒絕通知、「外部控制」分頁、對照表與複製、設定檔讀寫。
6. **全域快捷鍵**：註冊／清除、衝突顯示、重新開啟時恢復註冊。
7. **文件與驗收**：更新 `app/README.md`；Windows 以 Stream Deck「開啟」動作（網址與執行檔加參數兩種）、AutoHotkey 與快捷鍵實按，App 開著與未開啟兩種情況都要測，人工確認掛燈變化後記錄於 `docs/DEVELOPMENT_ACCEPTANCE.md`。macOS、iOS 另行驗收。

每一步都需通過 `app/` 既有檢查（`npm test`、`cargo test`、`cargo clippy -D warnings`、`cargo fmt --check`、debug 建置）。

## 待實測確認

- Stream Deck「系統 → 開啟」在 Windows 與 macOS 上能否直接開啟 `halodesk://` 網址。
- 每次觸發從按下到送出命令的延遲（命令列多一次程序啟動）；App 未開啟時從按下到情境套用的總時間。
- 主視窗最小化時，WebView 是否仍及時處理外部事件（系統匣選單目前在最小化時可用）。
